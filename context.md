## Stack and layout
- `backend/` FastAPI (Python 3.12, Pydantic v2). In-memory Firestore/GCS fallbacks in demo mode, so no GCP credentials are needed.
- `frontend/` Next.js 15.1.3 App Router + React 19, Tailwind v4. Browser calls go through the route handler `/api/proxy/*` → `API_BASE`; **SSE goes directly** to `NEXT_PUBLIC_API_BASE` (CORS allows `http://localhost:3000`).

## API contracts the UI codes against
- Errors: `{code, message, detail, request_id}` — 404 `NOT_FOUND`, 409 `CONFLICT` (run in progress), 422 `VALIDATION_ERROR` (empty bundle, bad input), plus (since the API-edge round) 413 `PAYLOAD_TOO_LARGE`, 429 `RATE_LIMITED` / `SERVICE_BUSY` (both with `Retry-After`), 405 `METHOD_NOT_ALLOWED`; EVERY error answers this envelope, FastAPI's own 422/404/405 included (see "API edge contract"). `lib/api.ts` throws it as a plain object; use `lib/errors.ts` (`toErrorEnvelope`, `isNotFound`, `runErrorMessage`).
- `data_source` (`"live" | "fixture" | null`) is returned by `GET /assessment` **and** `/iterations`, derived from what actually ran (`extraction_source == fixture` OR `grounding_source == seed` → `fixture`; `null` if nothing reported). It is never inferred from APP_MODE.
- `GET /bundles/{id}` · `/assessment` (404 until first run) · `/iterations` · `/audit` → `{events[{event_id,bundle_id,iteration,seq,ts,actor,event_type,payload,prev_hash,hash}], verified, error}` · `/documents/{docId}/file` (PDF) · `GET /meta` → `{app_mode, data_source_policy}`.
- Demo only (404 unless `APP_MODE=demo`): `POST /demo/case-c` (bundle `CASE-C-7304-DEMO`, SG, 3 PDFs; MTC withheld) and `GET /demo/case-c/mtc`. Fixture dir: repo `fixtures/case_c/`, override `CASE_C_FIXTURE_DIR`. A missing fixture answers 500 `The Case C sample documents are not installed on this server.` (the path goes to the log only).
- Run lifecycle (orchestrator owns the audit events; there is no generic "audit" stage): `ANALYSIS_STARTED` → stages `preprocess, extract, discrepancy, ground, confidence, synthesize` → `finalize` (progress 0.98) → iteration persisted → `ASSESSMENT_COMPLETED` → run `COMPLETE`. Any failure → run `ERROR` + `ANALYSIS_FAILED` (best effort, bounded to 5 s) with a PUBLIC message (see "Run lifecycle contract" below; never the raw exception text). `ASSESSMENT_COMPLETED` only exists for a persisted iteration. `"SYSTEM_EVENT"` survives only as `audit.record`'s default when a caller passes no type (no caller does).
- Audit hash = `sha256(canonical_json({prev_hash, seq, ts, bundle_id, iteration, event_type, actor, payload}))` (one JSON object, no string concatenation). Chains written with the older concatenated format do not verify.
- Live mode (`APP_MODE=live`) never uses fixtures: extraction raises `ExtractionError("no processable pages")` when there is nothing to send, and a per-document preprocess failure fails the run (demo mode warns and continues).

Config: JSON mime type, `response_schema=ExtractedDocument`, temperature 0, `max_output_tokens`, `thinking_config` only when `GEMINI_THINKING_BUDGET >= 0`. Every page is preceded by a `Page N of M.` text part (a single raw-PDF passthrough gets none and its page count is unknown); the prompt says `bbox.page` comes from those labels and that document text is data, not instructions.
  - The answer is read from `response.text` (not `.parsed`): ```` ```json ```` fence stripped, `json.loads`, then `_sanitise_extraction(raw, page_count)`: for every dict with `value` AND `confidence`, confidence is clamped to [0,1] (non-number -> 0) and `bbox` becomes `None` if it is not an object, has a non-numeric / outside-[0,1000] coordinate, `ymax <= ymin`, `xmax <= xmin`, page < 1, or page > `page_count`. The document-level `doc_type_confidence` is clamped the same way (warning path `doc_type_confidence`). It never changes `value`, `unit` or `doc_type`. Dropped boxes / clamps go to `ctx["extraction_warnings"]` (`{document_id, path, reason}`).

- Reasoning Delta credits a newly uploaded document only when its (extraction-refreshed) `doc_type` exactly equals the type in the requirement id (`ME-CORE-<T>` / `ME-<T>`); otherwise "Requirement for <label> is no longer triggered."
- SSE `GET /bundles/{id}/stream`: **named** events `status` (has `kind:"status"`, `state`, `stage`, `progress`, `run_id`, `message?`) and `iteration` (full iteration, no `kind`). Replays current status + latest iteration on connect, then only on change. The SSE iteration is the stored iteration dict (includes `data_source`, same as `GET /assessment`). An unknown bundle is a 404 with the standard envelope BEFORE the stream opens (it used to answer 200 and invent a status). Polling is adaptive: `STREAM_POLL_ACTIVE_SECONDS` (1.0) while the run is RUNNING/QUEUED, `STREAM_POLL_IDLE_SECONDS` (3.0) otherwise, and it is only the FALLBACK: the orchestrator wakes the stream at once on every run-record write (see "Run lifecycle contract" -> wake-up channel); module seam `stream._sleep` (the poll timer that the wake-up races); each cycle that finds RUNNING calls `orchestrator.reap_stale`, so nobody watches a dead run forever. A failure inside the stream emits `event: error` with the FIXED message `The event stream failed unexpectedly` and code `STREAM_EXCEPTION` (exception logged, never sent); a client disconnect is logged at info and the `CancelledError` re-raised. The generator is `stream.event_stream(bundle_id)` (tests drive it directly; ASGITransport buffers streams).
- `check_id` is unique within an iteration: duplicate-document checks are `D-DUP-<DOCTYPE>` (e.g. `D-DUP-PACKING_LIST`), one per duplicated type. The UI still keys rows on `check_id:index` defensively.
- **Deterministic rules (since 2026-10-10).** Engine rule: a check whose result depends on an ASSUMPTION never returns PASS or MATERIAL; it returns WARN, lists every assumption in `CheckResult.assumptions` (new, `list[str]`, default `[]`) and states the computed delta in the message. Check ids: `W-001` (packing list vs BoL gross), `W-002` (packing list adds up; only when it declares net, tare AND total gross), `H-002`, `H-003-<DOCTYPE>` (certificate HS vs invoice), `G-001` (HS classification), `E-consignee` / `E-consignor` / `E-vessel`, `D-DUP-<DOCTYPE>`.
  - W-001 packing-list side, in priority order: (1) net + DECLARED tare, (2) the packing list's DECLARED total gross (tare not declared), (3) last resort net + 2% default tare, which is always a WARN with assumption `tare not declared; assumed 2% of net (spec default)`. `DEFAULT_TARE_RATIO` is used nowhere else. Tolerance unchanged: `max(0.5% x BoL gross, 5 kg)`.
  - Units: weight fields (`total_net/gross_weight_kg`, `tare_weight_kg`, line `net/gross_weight_kg`) are `QuantityRef` = `FieldRef` + `unit` (as printed, never converted at extraction; a plain `FieldRef` is coerced to `QuantityRef(unit=None)`). `app/domain/units.py` parses numbers and converts to kg: no unit -> assumption `no unit stated; assumed kg`; unrecognised unit -> check WARN "not evaluable"; ambiguous separators ("14,280") -> assumption. A unit printed inside the value ("14,280 KGS") counts as stated.
  - H-002 compares digits only (`7304.19.00` == `73041900`) from line items AND `hs_code_header`: at 8 digits when every code states 8 (longer codes truncated to 8, stated in the message), otherwise at 6 digits and an agreement is a WARN (`compared at 6 digits; 8-digit AHTN code not stated`). Codes with < 6 digits are "malformed HS code '<raw>'": never compared.
  - Case C fixtures print and carry unit `KGS` on every weight; `fixtures/case_c/*.pdf` print "14000.0 KGS". Case C outcome is unchanged: iteration 1 MISSING_EVIDENCE with W-001, W-002, H-002 PASS; iteration 2 COMPLIANT.
- **HS handling and grounding (since 2026-10-10).** `app/domain/hs.py` is the single reader of HS codes (`hs_text`, `hs_digits`, `hs_match_level`: exact8 / subheading6 / heading4 / none / not_declared); H-002 and grounding both use it, so `"7304.19.00"`, `"7304 19 00"`, `73041900`, `73041900.0` are the same code everywhere.
  - Text fields are `TextRef` (value always a string; numbers become text, whole floats lose `.0`); numeric fields stay `FieldRef`, weights are `QuantityRef`. JSON keys are unchanged.
  - Grounding (`agents/grounding.py`): the query is the line DESCRIPTION ONLY (never the declared code); the declared code is matched against every candidate and the best level wins (ties: lowest distance) = the GOVERNING row. Policy: exact8 -> required documents from the governing row, ambiguous only if its distance > 0.35; subheading6 -> ambiguous, no documents; heading4/none -> `hs_mismatch` + ambiguous, no documents; not_declared (no/short code or no description) -> ambiguous, no documents. Certificates (MTC, certificate of origin, phytosanitary) are not grounded: their lines describe a test, not goods.
  - `GroundingFinding` gained `hs_match_level`, `governing_hs`, `rule_set`, `regulation_ref` (all optional; null on older iterations); `top_candidate_*`/`distance` describe the row the line was judged against (the governing row, else the top-ranked one). `MissingEvidence` gained `rule_set`.
  - **G-001 "HS classification"** is appended to `checks` after grounding, exactly one per iteration: PASS iff every grounded line is exact8, not ambiguous and had a description, else WARN (never MATERIAL; with no grounded lines: WARN "not performed"). It does not change status resolution. H-002 and G-001 evidence entries carry `line_item`, `page`, `bbox`, `raw_value` when known.
  - **Wording rule:** requirements come from a curated DEMO rule set and are never described as official. Constants live in `app/domain/provenance.py`: `rule_set = "demo-curated"`, `regulation_ref = "Demo rule set (prototype); not an official AHTN requirement"`, core-document reason/ref ("Prototype baseline rule"). ## Run lifecycle contract (since the run-lifecycle round)
- **One instance.** The API runs as ONE instance (Cloud Run max-instances=1 is planned), so the run claim is an in-process `asyncio.Lock` per bundle, not a Firestore transaction. Durable backstops: iteration documents are create-only (`firestore.write_iteration` uses `.create()`; a second write of the same number raises `PipelineError("iteration N already exists for bundle X")`), and audit appends `.create()` at document id `f"{seq:010d}"`.
- **Claim (`orchestrator.start_run`).** Under `_START_LOCKS[bundle]`: read the bundle (empty -> 422) -> `reap_stale` -> if a RUNNING run remains -> 409 `CONFLICT` (detail `run_id`) -> iteration = `max(bundle.current_iteration, latest_iteration) + 1` -> write the run record `initializing`. Two simultaneous `/analyze` calls give one 202 and one 409 even when the store yields. A failed run does not burn its iteration number.
- **Heartbeat.** While a run executes a task `heartbeat-<run_id>` calls `firestore.touch_run` every `RUN_HEARTBEAT_SECONDS` (10). `touch_run` changes ONLY `updated_at` and ONLY while the stored state is RUNNING (it never creates or revives a record). The heartbeat is cancelled AND awaited before any terminal state is written, and in a `finally`.
- **Stale = dead.** A RUNNING record whose `updated_at` is older than `RUN_STALE_AFTER_SECONDS` (90; settings validator: >= 3 x the heartbeat) or has no usable timestamp belongs to a dead process. `orchestrator.reap_stale(bundle_id)` (under `_REAP_LOCKS`, lock order start -> reap) marks it ERROR (`The analysis was interrupted (no heartbeat)`) and writes ONE `ANALYSIS_FAILED` (`reason: "interrupted"`, iteration and mode read back from its `ANALYSIS_STARTED` event); idempotent because it only acts on RUNNING. Called from `start_run` and from the SSE poll loop. The old 600 s in-flight window is gone.
- **Deadline.** The whole pipeline runs under `asyncio.timeout(RUN_TIMEOUT_SECONDS)` (1200): ERROR `the analysis exceeded the time limit`, audit `reason: "timeout"`.
- **Cancellation.** `_execute_pipeline` handles `CancelledError`: stop the heartbeat, then ERROR `cancelled: the server is shutting down` + `ANALYSIS_FAILED` (`reason: "cancelled"`) under a shield bounded by `_CLEANUP_TIMEOUT_SECONDS` (5 s), then RE-RAISE (`task.cancelled()` is True). The FastAPI lifespan calls `orchestrator.shutdown(timeout=5)` on shutdown (cancel every running task and wait). SIGINT with an SSE stream open exits in under a second.
- **Public error rules.** `public_error(exc, run_id) -> {code, message}` (`app/gateway/errors.py`, re-exported by the orchestrator): a `CargoClearError` -> its own code and message (written to be shown, e.g. `ExtractionError`; the run deadline arrives as `RunTimeoutError`, code `RUN_TIMEOUT`, raised ONLY when `asyncio.timeout(...).expired()`); `CancelledError` -> `RUN_CANCELLED`; anything else, a stray `TimeoutError` (socket, client) included, -> `INTERNAL_ERROR` with `The analysis failed unexpectedly (reference: <run_id>).`. The run state `message` (and therefore the SSE status) and the `ANALYSIS_FAILED` audit payload `{run_id, mode, stage, error_type (class name), code, message[, reason]}` use it. The raw exception text goes to `logger.exception` only. **Never interpolate `{exc}` / `str(exc)` into a raised CargoClearError message or a stored/returned value: use `type(exc).__name__` and keep `from exc`** (a test greps `app/` for it).
- **Fencing.** A run that lost its claim (reaped while merely slow, or superseded) writes nothing more. `_ensure_claim(bundle_id, run_id)` reads ITS OWN run record and raises `RunInterruptedError("the run lost its claim")` unless it is RUNNING; it runs before every stage write (a stage write would turn the reaper's ERROR back into RUNNING) and right before `write_iteration` (so no iteration and no `ASSESSMENT_COMPLETED`). `_fail_run` does nothing when the stored state of its run is already ERROR (no second `ANALYSIS_FAILED`, no overwrite). The COMPLETE write is `firestore.set_run_state(..., only_if_state="RUNNING") -> bool`; a refused write logs `run_complete_not_applied`. On Firestore these are read-then-write, not transactions.
- **Concurrency cap.** `MAX_CONCURRENT_RUNS` (4; 0 = off): under the claim lock, AFTER the empty-bundle (422) and in-flight (409) checks and BEFORE any run record is written, `start_run` counts live runs (`_RUNNING_TASKS` not done + `_starting_runs`, a reservation counter so starts on different bundles cannot overshoot together) and refuses the next with 429 `SERVICE_BUSY` ("The service is busy analysing other bundles. Try again shortly.") and `Retry-After: 5`. A finished, failed or cancelled run frees its slot.
- **Wake-up channel (`services/run_events.py`).** `subscribe(bundle_id)` -> `Subscription` (context manager; `wait(timeout)`, `close()`), `notify(bundle_id)`, and a one-shot module-level `wait(bundle_id, timeout)`. Per bundle a channel holds a version counter; each subscription remembers the version it has seen, so a `notify` that lands while the listener is busy (between two waits, or between `subscribe` and the first wait) makes the next `wait` return at once. A channel exists only while it has subscribers; `notify` for a bundle nobody listens to creates nothing. The orchestrator calls `notify` after the claim, every stage write, `write_iteration`, COMPLETE, a failure (`set_run_error`) and a reap. The SSE stream subscribes BEFORE its first read and waits `min(wake-up, poll interval)`; a lost notify costs at most one poll interval. The heartbeat does not notify.
- **Settings:** `RUN_HEARTBEAT_SECONDS=10`, `RUN_STALE_AFTER_SECONDS=90`, `RUN_TIMEOUT_SECONDS=1200`, `STREAM_POLL_ACTIVE_SECONDS=1.0`, `STREAM_POLL_IDLE_SECONDS=3.0`, `MAX_CONCURRENT_RUNS=4` (all in `.env.example`).
- **Audit append.** On Firestore: tail read -> `create()` at `{seq:010d}` -> on `AlreadyExists` re-read the tail and retry, at most 5 times, then `UpstreamError` in live mode (logged in demo mode). The stored `event_id` field keeps its format (`bundle:iteration:seq`); the hash chain is unchanged. Event documents written before this round have the old id format.
- The made-up `COMPLETE` / `"Ready"` status for a bundle with no runs stays (a later UI task owns it). Run records are unchanged in shape (no new keys).

## API edge contract (since the API-edge round)
- **Middleware order** (outermost first; all PURE ASGI, so the SSE stream is never wrapped or buffered): `RequestContext` -> `SecurityHeaders` -> `CORS` -> `RateLimit` -> `BodySizeLimit` -> `ErrorEnvelope` -> routes. Everything the guards refuse still carries the request id, the security headers and the CORS headers. `main.create_app()` builds the app (module-level `app = create_app()`); tests that need another configuration call `create_app()` after patching `settings`.
- **Request id.** An inbound `X-Request-ID` is kept only if it fullmatches `[A-Za-z0-9._-]{1,64}`, otherwise a uuid4 replaces it. The SAME id is the response header (set once), the envelope's `request_id` (also when the client sent none) and the log context (`request_id`, `method`, `path`; cleared when the request ends).
- **Error envelope for everything.** `RequestValidationError` -> 422 `VALIDATION_ERROR`, message `The request is not valid.`, `detail = {"errors": [{loc, msg, type}]}` (never the input value, `ctx` or `input`); Starlette `HTTPException` -> 404 `NOT_FOUND` `Resource not found.`, 405 `METHOD_NOT_ALLOWED` `Method not allowed.` (the `Allow` header is kept), any other status `HTTP_<status>` with `The request could not be processed.` (never `exc.detail`). `CargoClearError` and unhandled exceptions are unchanged (the latter: 500 `INTERNAL_ERROR`, `An unexpected error occurred. Please retry.`, no exception text). `CargoClearError.headers` carries extra response headers (`Retry-After`).
- **Security headers** on every response: `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`; `Cache-Control: no-store` on `application/json` responses that set none. SSE keeps its own headers; downloads use `Cache-Control: private, max-age=3600`.
- **Path ids.** `bundle_id` / `document_id` must fullmatch `[A-Za-z0-9][A-Za-z0-9_-]{0,63}` (an app-wide dependency, `gateway/ids.py`), else the same 404 `NOT_FOUND` an unknown id gets (message template `Bundle '<id>' not found.` with the id bounded to 64 printable characters), on every route including `/stream`. Local demo storage builds file paths from these ids. Note `GET /bundles/{unknown}/iterations` has always answered 200 `[]`.
- **Body size** (`BodySizeLimitMiddleware`): POST/PUT bodies are limited to `MAX_JSON_BODY_KB` (256), except `POST /bundles/{id}/documents`: `MAX_UPLOAD_MB` (50) + 1 MB. A `Content-Length` over the limit -> 413 `PAYLOAD_TOO_LARGE` BEFORE one byte is read; without one the bytes are counted while they stream and the 413 is sent as soon as the limit is crossed. Messages: `The request body is larger than 256 KB.` / `The file is larger than 50 MB.`
- **Uploads** (`api/v1/documents.py`, `services/upload_checks.py`): the handler reads in 1 MiB chunks and answers 413 as soon as `MAX_UPLOAD_MB` is crossed (never holds more than limit + one chunk); 0 bytes -> 422. Then, in a worker thread: `%PDF-` within the first 1024 bytes (`The file is not a PDF.`), no `/Encrypt` (`Password-protected PDFs are not supported.`), and when poppler's `pdfinfo` works at most `GEMINI_MAX_PAGES` pages (`The document has N pages; the limit is M.`; no poppler or a PDF pdfinfo cannot parse -> skipped, info log `pdf_page_count_skipped`). Cap: a new DISTINCT document in a bundle already holding `MAX_DOCUMENTS_PER_BUNDLE` (20) -> 422 `A bundle can hold at most 20 documents.`; identical bytes (same content-addressed id) are NOT counted and keep the old behaviour (201, the record is replaced with the new name and type UNKNOWN, another `DOCUMENT_UPLOADED` event); the count and the registration run under a per-bundle lock.
- **File names.** `register_document` stores, audits and classifies `sanitize_filename(name)`: last path component (`/` and `\`), control and format characters (CR/LF, NUL, bidi overrides, zero-width) and quotes dropped, whitespace collapsed, cut to 150 characters keeping the extension, `document.pdf` when nothing is left (empty or only dots); non-ASCII is kept. Downloads (documents route and the demo MTC route) send `Content-Disposition: inline; filename="<ascii fallback>"; filename*=UTF-8''<percent-encoded>` (fallback: every non-ASCII, control, quote, backslash and `%` becomes `_`; safe for any stored name), `Cache-Control: private, max-age=3600`, `X-Content-Type-Options: nosniff`.
- **CreateBundleRequest.** `reference`: control characters removed, stripped, at most `MAX_REFERENCE_CHARS` (200; longer -> 422, never truncated); `destination_country` must match `^[A-Za-z]{2}$` (upper-cased by the route). The `BUNDLE_CREATED` audit payload is therefore small.
- **Rate limits** (`gateway/limits.py`, in-process fixed window of 60 s, injectable clock, idle buckets dropped): per client address, class `writes` = `POST /bundles`, `POST /bundles/{id}/documents`, `POST /demo/case-c` (`RATE_LIMIT_WRITES_PER_MINUTE`, 60), class `runs` = `POST .../analyze`, `.../reassess` (`RATE_LIMIT_RUNS_PER_MINUTE`, 10); 0 switches a class off. Over the limit -> 429 `RATE_LIMITED`, `Retry-After: N` (>= 1), `Too many requests. Try again in N seconds.`, refused before the body is read. GET routes and the stream are never limited. Key = the socket peer, or with `TRUST_FORWARDED_FOR=true` the first valid IP in `X-Forwarded-For` (malformed -> the peer). `tests/conftest.py` resets the limiter for every test. There is no API-key scheme: the browser opens the SSE stream directly (EventSource cannot send headers), authentication is an infra decision (P10).
- **API docs.** `ENABLE_API_DOCS` (unset = on when `APP_MODE=demo`, off when `live`): `/docs`, `/redoc`, `/openapi.json` answer the 404 envelope when off. `/healthz`, `/readyz`, `/meta` unchanged.
- **Settings added:** `MAX_UPLOAD_MB=50`, `MAX_JSON_BODY_KB=256`, `MAX_DOCUMENTS_PER_BUNDLE=20`, `MAX_REFERENCE_CHARS=200`, `RATE_LIMIT_WRITES_PER_MINUTE=60`, `RATE_LIMIT_RUNS_PER_MINUTE=10`, `MAX_CONCURRENT_RUNS=4`, `TRUST_FORWARDED_FOR=false`, `ENABLE_API_DOCS` (commented out); sizes must be > 0, counts >= 1, rates and the run cap >= 0.
- **Test helpers.** `tests/helpers.asgi_call(method, path, body=|chunks=, content_length=, client=, until=)` calls the real app below httpx (no URL normalisation, a chunked body, `receive_calls`, early return for SSE).
